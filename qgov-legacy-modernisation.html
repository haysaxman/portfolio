QGov Legacy Modernisation

Context

I led the design work for the modernisation of a decades-old desktop application that had become slow, unreliable, and difficult to maintain. The product ecosystem consisted of multiple applications managing overlapping data, resulting in syncing issues and inconsistent records. Documentation was sparse, and while subject-matter experts understood individual areas well, no one had a complete view of user journeys across the system.

Note: Any specifics of this project have been removed due to contractual obligation.

Design Challenge

The primary challenge was to modernise the application but maintain a like-for-like appearance to avoid disrupting existing users. Design decisions needed to balance usability improvements with a strong respect for existing workflows the users had been familiar with for years. Lack of documentation meant there would need to be heavy investigation into the existing application and the daily workflows of the users.

We were required to combine the previously separate desktop applications into a inter-connected web application that allowed for consolidating common data through a core database while also maintaining separate databases for each application.

Approach

Because best-practice redesign patterns weren’t always appropriate, I focused on deeply understanding the legacy experience before designing anything new. I spent significant time hands-on testing the original application to uncover undocumented features, edge cases, and workflows. I worked closely with the Government-side project team to validate our findings and communicating options and changes for both design and processes.

Data integrity through the migration was of up most importance, so I worked closely with the developers to design a custom data-migration tool, ensuring that design decisions aligned with complex underlying data transformations.

Outcomes & Learnings

Testing the legacy application revealed significant hidden functionality that were neither documented or directly known by SMEs. This highlighted that earlier, more structured documentation of these discoveries would have improved feature planning and sequencing.

The care taken to respect existing user behaviour while subtly improving clarity and consistency paid off. Clients responded very positively to the familiarity of the new system and the confidence it gave users during transition. We did need to revisit some early data-consolidation assumptions when visually mapping fields revealed that seemingly duplicated data served different user needs across applications. In future projects, I would visualise these trade-offs earlier to better support shared decision-making with stakeholders.
